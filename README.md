# Pet Medication Tracker

> Мобильно-дружественное веб-приложение для отслеживания приёма лекарств у домашних животных

---

## 🎯 Описание проекта

Помогает владельцам животных не пропускать приём препаратов: курс лечения ссылается на препарат из личного каталога, система сама строит расписание доз и напоминает о них в дневном календаре. Целевая аудитория — владельцы животных на регулярном курсе лечения (антибиотики, хронические препараты, витамины), которым важно не забыть дозу.

## ✨ Возможности

- 🐾 **Питомцы** — карточки с фото, породой, весом, полом, репродуктивным статусом, заметками
- 📄 **Карточка питомца в PDF** — общая информация, выбранные диагнозы, курсы препаратов и приёмы врача за выбранный период, по желанию — записи дневника состояния
- 🩻 **Диагнозы питомца** — на карточке питомца: название, отметка «подтверждён врачом» (и тогда обязательно имя врача), комментарий
- 📖 **Дневник состояния** — на карточке питомца: заметки до 500 символов с автоматической датой и временем создания; можно редактировать, удалять по одной или отметить несколько и удалить разом
- 💊 **Каталог препаратов** — свой у каждого пользователя: название, «для чего», дозировка в одной таблетке
- 📅 **Курсы лечения** — дозировка за приём, частота, время напоминаний; расписание доз на весь курс строится автоматически (если дата окончания не указана — до конца текущего календарного года)
- 🩺 **Приём врача** — дата/время приёма и отдельное время напоминания (не позже приёма), врач (опционально), комментарий; клиника выбирается из своего каталога клиник или создаётся на лету. Кнопка «Приём состоялся» (с подтверждением) закрывает приём для редактирования и переносит его в историю питомца — вкладка «Приёмы врача» в статистике
- 🏥 **Каталог клиник** — название, адрес, телефон (строго цифры) — все обязательны, сайт — опционально, его можно очистить
- ✅ **Дневной и месячный календарь** — отметка приёма («принято» / «пропущено» / «не принято»); просроченные дозы помечаются автоматически, а пропущенная доза не «теряется» — вместо неё дальше по графику появляется новая. Мини-календарь подсвечивает день: ярко-голубая рамка — все дозы приняты, серая — что-то не принято, красная (наивысший приоритет) — в этот день приём врача
- 🛑 **Отмена или удаление курса** — с сохранением истории уже отмеченных приёмов в календаре
- 📈 **Статистика** — живая сводка по текущим курсам (сколько принято, сколько осталось), завершённые курсы и история состоявшихся приёмов врача
- 🧮 **Калькулятор количества препарата** на весь курс (таблетки/жидкость) прямо в форме создания курса
- ⚙️ **Настройки** — формат времени: 24 часа (`20:30`) или 12 часов (`8:30 PM`)
- 🔑 **Аутентификация** — JWT, восстановление пароля по email
- 🐞 **Сообщения об ошибках** — пользователь пишет свободным текстом, разбор через API/Swagger
- 📊 **Логирование и мониторинг** — структурированные JSON-логи, готовый дашборд Grafana + Loki

## 🚀 Быстрый старт

### Установка (Docker)

```bash
# Клонирование
git clone https://github.com/AlenaSygrysheva/pets_medication_tracker.git
cd pets_medication_tracker

# Конфигурация
```

## 📊 Мониторинг и логирование

- Логи: одна строка = один JSON-объект в stdout (`app/core/logging.py`), поля `timestamp`, `level`, `logger`, `message`, плюс всё, что передано через `extra=` (например middleware добавляет `http_method`, `http_path`, `status_code`, `duration_ms` к логу каждого запроса)
- Стек логирования (поднимается вместе с остальными сервисами через `docker compose up -d`):
  - **Promtail** — читает логи контейнера `app` через Docker API и отправляет в Loki, попутно вытаскивая поле `level` из JSON как label
  - **Loki** — хранилище логов (локальный диск, `retention_period: 168h` — неделя)
  - **Grafana** (`http://localhost:3001`, `admin`/`admin` по умолчанию — сразу смените в `.env` через `GRAFANA_ADMIN_USER`/`GRAFANA_ADMIN_PASSWORD`) — датасорс Loki и дашборд «App Logs» подключены автоматически (provisioning), на нём: счётчики Warning/Error+Critical за последний час, график объёма логов по уровням, поток логов уровня `WARNING`/`ERROR`/`CRITICAL`
  - В Grafana можно донастроить алерты (Alerting → Contact points/Alert rules) поверх тех же Loki-запросов, если нужны уведомления, а не только дашборд
- Health check: `GET /health` — статус приложения и версия
- Метрики (Prometheus) и трейсинг (OpenTelemetry) пока не подключены

### Питомцы

`sex` — `male` / `female` / `unknown` (по умолчанию). `reproductive_status` — `intact` (не стерилизовано) / `sterilized` (стерилизовано) / `unknown` (неизвестно, по умолчанию).

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/pets` | Список питомцев пользователя |
| `POST` | `/api/v1/pets` | Добавить питомца |
| `GET` | `/api/v1/pets/{id}` | Карточка питомца |

| `POST` | `/api/v1/pets/{id}/avatar` | Загрузить фото |

| `DELETE` | `/api/v1/pets/{id}` | Удалить питомца |

### Каталог препаратов

Препарат — это справочная запись (название, «для чего», дозировка в одной таблетке), независимая от питомцев. Каталог у каждого пользователя свой. Одинаковое название с разной дозировкой — разные записи («Энроксил 15 мг» и «Энроксил 25 мг»); полный дубликат название+дозировка запрещён (`409`).

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/drugs` | Каталог препаратов пользователя (без удалённых) |
| `POST` | `/api/v1/drugs` | Добавить препарат в каталог |
| `GET` | `/api/v1/drugs/{id}` | Карточка препарата |
| `PATCH` | `/api/v1/drugs/{id}` | Редактировать препарат |
| `DELETE` | `/api/v1/drugs/{id}` | Удалить препарат из каталога (мягко). Запрещено (`409`), если препарат используется хотя бы в одном активном курсе; история приёмов в календаре сохраняется в любом случае |

### Курсы лечения

Курс — это применение препарата из каталога к конкретному питомцу: дозировка за один приём, частота, время напоминаний, даты начала/окончания.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/medications/pet/{pet_id}` | Курсы лечения питомца (без удалённых) |
| `GET` | `/api/v1/medications/pet/{pet_id}/stats/active` | Живая сводка по текущим курсам (ещё идут: есть хотя бы одна ожидающая доза) — сколько уже принято/пропущено/не принято и сколько осталось (`pending`) |
| `GET` | `/api/v1/medications/pet/{pet_id}/stats` | Сводка по завершённым курсам (отменённым или без оставшихся ожидающих доз) |
| `POST` | `/api/v1/medications` | Создать курс по `drug_id` (генерирует дозы по `reminder_times`) |
| `GET` | `/api/v1/medications/{id}` | Карточка курса (включает вложенный объект `drug`) |
| `PATCH` | `/api/v1/medications/{id}` | Редактировать курс |
| `POST` | `/api/v1/medications/{id}/cancel?as_of_date=` | Отменить курс на указанную дату (по умолчанию — сегодня): дозы после неё стираются из календаря, дозы до и в этот день помечаются `cancelled` |
| `DELETE` | `/api/v1/medications/{id}` | Мягкое удаление курса: пропадает из списка, но уже отмеченные дозы (`taken`/`skipped`/`missed`) остаются в календаре |

Пропущенная (`missed`) или непринятая вручную доза не сокращает курс — вместо неё автоматически создаётся новая доза дальше по графику (`MedicationService.extend_after_unresolved_dose`), пока курс не отменят явно. Курс считается «завершённым» не по дате окончания, а по отсутствию ожидающих доз (или по отмене) — до этого момента он live-обновляется во вкладке «Текущие». Каждая запись в сводке несёт поле `status` (`active` / `completed` / `cancelled`) вместо старого `ended_reason`.

### Календарь и дозы

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/calendar/month/{year}/{month}` | Мини-календарь на месяц: по каждому дню — питомцы (инициалы) с запланированными приёмами, агрегированный статус дня (`status`) и флаг `has_vet_appointment` |
| `GET` | `/api/v1/calendar/pet/{pet_id}/{date}` | Расписание дня (YYYY-MM-DD) |
| `PATCH` | `/api/v1/doses/{id}` | Отметить дозу (taken / skipped / missed) |

Каждый день в ответе месячного календаря несёт `status` (`all_taken` / `partial` / `none`) и `has_vet_appointment`. На мини-календаре это рисуется рамкой: ярко-голубая — все дозы дня приняты (`all_taken`), серая — что-то не принято (`partial`), обычная — ничего не отмечено (`none`). Красная рамка (приём врача, `has_vet_appointment`) приоритетнее всех остальных и не уступает им, даже если в этот день все дозы приняты.

### Каталог клиник

Клиника — справочная запись (название, адрес, телефон, необязательный сайт), независимая от питомцев; приём врача ссылается на клинику из каталога. `address` и `phone` обязательны, `phone` — строго цифры (7–15 символов, без `+`, пробелов и дефисов). Дубликат по имени (у одного пользователя) запрещён (`409`). При `PATCH` применяются только присланные поля: `website: null` или пустая строка очищают сайт, а название, адрес и телефон очистить нельзя (`422`).

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/clinics` | Каталог клиник пользователя (без удалённых) |
| `POST` | `/api/v1/clinics` | Добавить клинику в каталог |
| `GET` | `/api/v1/clinics/{id}` | Карточка клиники |
| `PATCH` | `/api/v1/clinics/{id}` | Редактировать клинику |
| `DELETE` | `/api/v1/clinics/{id}` | Удалить клинику (мягко). Запрещено (`409`), если на неё запланирован будущий приём врача |

### Приём врача

Привязан строго к одному питомцу. `appointment_at` (дата и время приёма) обязательно; `reminder_at` (время напоминания) обязательно и не может быть позже `appointment_at` (проверяется и при создании, и при редактировании). `doctor_name` и `comments` — опциональны.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/vet-appointments?pet_id=` | Приёмы пользователя, опционально отфильтрованные по питомцу |
| `POST` | `/api/v1/vet-appointments` | Создать приём (`pet_id`, `clinic_id`, `appointment_at`, `reminder_at`, опц. `doctor_name`, `comments`) |
| `GET` | `/api/v1/vet-appointments/{id}` | Карточка приёма |
| `PATCH` | `/api/v1/vet-appointments/{id}` | Редактировать приём |
| `DELETE` | `/api/v1/vet-appointments/{id}` | Удалить приём |
| `POST` | `/api/v1/vet-appointments/{id}/complete` | «Приём состоялся»: снимок приёма (с данными клиники) сохраняется в историю `completed_vet_visits`, сам приём удаляется — больше не редактируется и не отмечается в календаре |
| `GET` | `/api/v1/vet-appointments/completed?pet_id=` | История состоявшихся приёмов (новые сверху) |

### Диагнозы

Привязаны строго к одному питомцу. `confirmed_by_vet` — чекбокс «подтверждён врачом»; если он `true`, `doctor_name` обязателен (проверяется и при создании, и при редактировании). `comments` — опционально.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/diagnoses?pet_id=` | Диагнозы пользователя, опционально отфильтрованные по питомцу |
| `POST` | `/api/v1/diagnoses` | Создать диагноз (`pet_id`, `name`, опц. `confirmed_by_vet`, `doctor_name`, `comments`) |
| `GET` | `/api/v1/diagnoses/{id}` | Карточка диагноза |
| `PATCH` | `/api/v1/diagnoses/{id}` | Редактировать диагноз |
| `DELETE` | `/api/v1/diagnoses/{id}` | Удалить диагноз |

### Карточка питомца в PDF

`POST /api/v1/pets/{id}/report` → `application/pdf`. Тело: `date_from`, `date_to` (период лечения — курсы и приёмы врача, пересекающиеся с ним), `diagnosis_ids`, `diary_entry_ids` (что включить), опц. `tz_offset_minutes` (как `Date.getTimezoneOffset()` в браузере — для времени записей дневника) и `time_format` (`24` / `12`). Чужой или несуществующий id → `404`.

Состав карточки: общая информация (кличка, пол, вес, репродуктивность); выбранные диагнозы; лечение за период — препараты («Завершён» / «В процессе», дозировка, начало и конец курса по фактической последней дозе) и приёмы врача (запланированные и состоявшиеся, со всеми данными записи); выбранные записи дневника состояния — раздел появляется, только если что-то выбрано.

### Дневник состояния

Заметки привязаны к питомцу, новые сверху. `text` — 1–500 символов (пробелы по краям обрезаются), `created_at` проставляется сервером и при редактировании не меняется.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/diary-entries?pet_id=` | Заметки пользователя, опционально по питомцу |
| `POST` | `/api/v1/diary-entries` | Создать заметку (`pet_id`, `text`) |
| `GET` | `/api/v1/diary-entries/{id}` | Заметка |
| `PATCH` | `/api/v1/diary-entries/{id}` | Изменить текст |
| `DELETE` | `/api/v1/diary-entries/{id}` | Удалить заметку |
| `POST` | `/api/v1/diary-entries/bulk-delete` | Удалить несколько (`ids`); если хоть одна не найдена — не удаляется ничего (`404`) |

### Статусы дозы

| Статус | Описание |
|---|---|
| `pending` | Запланирована, ещё не принята |
| `taken` | Принята |
| `skipped` | Пропущена вручную |
| `missed` | Просрочена (проставлена планировщиком) или отмечена как «не принято» |
| `cancelled` | Курс отменён — доза на день отмены или раньше него, оставлена для истории |

### Сообщения об ошибках

Пользователь может в любой момент нажать 🐞 в шапке приложения и написать свободным текстом, что сломалось; сообщение сохраняется вместе с датой и его пользователем. Просмотр и разбор сообщений — только через API (`ADMIN_EMAIL` в `.env`), удобно через Swagger UI (`/docs`).

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/bug-reports` | Отправить сообщение об ошибке (любой авторизованный пользователь) |
| `GET` | `/api/v1/bug-reports?is_resolved=` | Список сообщений, опционально отфильтрованный по статусу (только `ADMIN_EMAIL`) |
| `PATCH` | `/api/v1/bug-reports/{id}` | Пометить сообщение решённым/нерешённым (только `ADMIN_EMAIL`) |
