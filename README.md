# Pet Medication Tracker

> Мобильно-дружественное веб-приложение для отслеживания приёма лекарств у домашних животных

---

## 🎯 Описание проекта

Помогает владельцам животных не пропускать приём препаратов: курс лечения ссылается на препарат из личного каталога, система сама строит расписание доз и напоминает о них в дневном календаре. Целевая аудитория — владельцы животных на регулярном курсе лечения (антибиотики, хронические препараты, витамины), которым важно не забыть дозу.

## ✨ Возможности

- 🐾 **Питомцы** — карточки с фото, породой, весом, заметками
- 💊 **Каталог препаратов** — свой у каждого пользователя: название, «для чего», дозировка в одной таблетке
- 📅 **Курсы лечения** — дозировка за приём, частота, время напоминаний; расписание доз на весь курс строится автоматически
- ✅ **Дневной и месячный календарь** — отметка приёма («принято» / «пропущено» / «не принято»); просроченные дозы помечаются автоматически, а пропущенная доза не «теряется» — вместо неё дальше по графику появляется новая
- 🛑 **Отмена или удаление курса** — с сохранением истории уже отмеченных приёмов в календаре
- 📈 **Статистика приёма** — живая сводка по текущим курсам (сколько принято, сколько осталось) отдельно от завершённых
- 🧮 **Калькулятор количества препарата** на весь курс (таблетки/жидкость) прямо в форме создания курса
- 🔑 **Аутентификация** — JWT, восстановление пароля по email
- 🐞 **Сообщения об ошибках** — пользователь пишет свободным текстом, разбор через API/Swagger
- 📊 **Логирование и мониторинг** — структурированные JSON-логи, готовый дашборд Grafana + Loki


## 📊 Мониторинг и логирование

- Логи: одна строка = один JSON-объект в stdout (`app/core/logging.py`), поля `timestamp`, `level`, `logger`, `message`, плюс всё, что передано через `extra=` (например middleware добавляет `http_method`, `http_path`, `status_code`, `duration_ms` к логу каждого запроса)
- Стек логирования (поднимается вместе с остальными сервисами через `docker compose up -d`):
  - **Promtail** — читает логи контейнера `app` через Docker API и отправляет в Loki, попутно вытаскивая поле `level` из JSON как label
  - **Loki** — хранилище логов (локальный диск, `retention_period: 168h` — неделя)
  - **Grafana** (`http://localhost:3001`, `admin`/`admin` по умолчанию — сразу смените в `.env` через `GRAFANA_ADMIN_USER`/`GRAFANA_ADMIN_PASSWORD`) — датасорс Loki и дашборд «App Logs» подключены автоматически (provisioning), на нём: счётчики Warning/Error+Critical за последний час, график объёма логов по уровням, поток логов уровня `WARNING`/`ERROR`/`CRITICAL`
  - В Grafana можно донастроить алерты (Alerting → Contact points/Alert rules) поверх тех же Loki-запросов, если нужны уведомления, а не только дашборд
- Health check: `GET /health` — статус приложения и версия
- Метрики (Prometheus) и трейсинг (OpenTelemetry) пока не подключены

## 📚 API документация

После запуска доступны Swagger UI (`/docs`) и ReDoc (`/redoc`). Все эндпоинты требуют JWT, кроме `/auth/register`, `/auth/login`, `/auth/refresh`, `/auth/forgot-password`, `/auth/reset-password` и `/health`.

### Аутентификация

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/auth/register` | Регистрация, возвращает токены |
| `POST` | `/api/v1/auth/login` | Вход, возвращает токены |
| `POST` | `/api/v1/auth/refresh` | Обновление access-токена |
| `GET` | `/api/v1/auth/me` | Данные текущего пользователя |
| `POST` | `/api/v1/auth/forgot-password` | Запросить ссылку для смены пароля на email (ответ одинаков независимо от того, зарегистрирован ли email) |
| `POST` | `/api/v1/auth/reset-password` | Сменить пароль по одноразовому токену из письма |

### Питомцы

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/pets` | Список питомцев пользователя |
| `POST` | `/api/v1/pets` | Добавить питомца |
| `GET` | `/api/v1/pets/{id}` | Карточка питомца |
| `PATCH` | `/api/v1/pets/{id}` | Редактировать питомца |
| `POST` | `/api/v1/pets/{id}/avatar` | Загрузить фото |
| `DELETE` | `/api/v1/pets/{id}` | Удалить питомца |

### Каталог препаратов

Препарат — это справочная запись (название, «для чего», дозировка в одной таблетке), независимая от питомцев. Каталог у каждого пользователя свой. Одинаковое название с разной дозировкой — разные записи («Энроксил 15 мг» и «Энроксил 25 мг»); полный дубликат название+дозировка запрещён (`409`).

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/drugs` | Каталог препаратов пользователя (без удалённых) |
| `POST` | `/api/v1/drugs` | Добавить препарат в каталог |
| `GET` | `/api/v1/drugs/{id}` | Карточка препарата |
| `PATCH` | `/api/v1/drugs/{id}` | Редактировать препарат |
| `DELETE` | `/api/v1/drugs/{id}` | Удалить препарат из каталога (мягко). Запрещено (`409`), если препарат используется хотя бы в одном активном курсе; история приёмов в календаре сохраняется в любом случае |

### Курсы лечения

Курс — это применение препарата из каталога к конкретному питомцу: дозировка за один приём, частота, время напоминаний, даты начала/окончания.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/medications/pet/{pet_id}` | Курсы лечения питомца (без удалённых) |
| `GET` | `/api/v1/medications/pet/{pet_id}/stats/active` | Живая сводка по текущим курсам (ещё идут: есть хотя бы одна ожидающая доза) — сколько уже принято/пропущено/не принято и сколько осталось (`pending`) |
| `GET` | `/api/v1/medications/pet/{pet_id}/stats` | Сводка по завершённым курсам (отменённым или без оставшихся ожидающих доз) |
| `POST` | `/api/v1/medications` | Создать курс по `drug_id` (генерирует дозы по `reminder_times`) |
| `GET` | `/api/v1/medications/{id}` | Карточка курса (включает вложенный объект `drug`) |
| `PATCH` | `/api/v1/medications/{id}` | Редактировать курс |
| `POST` | `/api/v1/medications/{id}/cancel?as_of_date=` | Отменить курс на указанную дату (по умолчанию — сегодня): дозы после неё стираются из календаря, дозы до и в этот день помечаются `cancelled` |
| `DELETE` | `/api/v1/medications/{id}` | Мягкое удаление курса: пропадает из списка, но уже отмеченные дозы (`taken`/`skipped`/`missed`) остаются в календаре |

Пропущенная (`missed`) или непринятая вручную доза не сокращает курс — вместо неё автоматически создаётся новая доза дальше по графику (`MedicationService.extend_after_unresolved_dose`), пока курс не отменят явно. Курс считается «завершённым» не по дате окончания, а по отсутствию ожидающих доз (или по отмене) — до этого момента он live-обновляется во вкладке «Текущие». Каждая запись в сводке несёт поле `status` (`active` / `completed` / `cancelled`) вместо старого `ended_reason`.

### Календарь и дозы

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/calendar/month/{year}/{month}` | Мини-календарь на месяц: по каждому дню — питомцы (инициалы) с запланированными приёмами, по всем питомцам пользователя |
| `GET` | `/api/v1/calendar/pet/{pet_id}/{date}` | Расписание дня (YYYY-MM-DD) |
| `PATCH` | `/api/v1/doses/{id}` | Отметить дозу (taken / skipped / missed) |

### Статусы дозы

| Статус | Описание |
|---|---|
| `pending` | Запланирована, ещё не принята |
| `taken` | Принята |
| `skipped` | Пропущена вручную |
| `missed` | Просрочена (проставлена планировщиком) или отмечена как «не принято» |
| `cancelled` | Курс отменён — доза на день отмены или раньше него, оставлена для истории |

### Сообщения об ошибках

Пользователь может в любой момент нажать 🐞 в шапке приложения и написать свободным текстом, что сломалось; сообщение сохраняется вместе с датой и его пользователем. Просмотр и разбор сообщений — только через API (`ADMIN_EMAIL` в `.env`), удобно через Swagger UI (`/docs`).

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/bug-reports` | Отправить сообщение об ошибке (любой авторизованный пользователь) |
| `GET` | `/api/v1/bug-reports?is_resolved=` | Список сообщений, опционально отфильтрованный по статусу (только `ADMIN_EMAIL`) |
| `PATCH` | `/api/v1/bug-reports/{id}` | Пометить сообщение решённым/нерешённым (только `ADMIN_EMAIL`) |

Для таблеток показывается точное число (например, «1.33 таблетки»), для жидкости — округление до сотых. Только подсказка на фронтенде, в БД не сохраняется
- В карточке отметки приёма (принято/пропущено/не принято) дозировка теперь подписана как «Дать 0.05 · 23:00» вместо голого «0.05 · 23:00»
- Каталог препаратов (`Drug`, миграция `007`) — препараты теперь заводятся отдельно от питомцев (название, для чего, дозировка в таблетке), курс лечения ссылается на препарат из каталога вместо ввода названия вручную; удаление препарата заблокировано, пока он используется в активном курсе, история приёмов в календаре сохраняется даже после удаления препарата из каталога
- Мини-календарь на месяц («Календарь» теперь открывается сеткой дней с инициалами питомцев, у которых есть приёмы) — `GET /calendar/month/{year}/{month}`; клик по дню открывает прежний дневной список
- Пропущенная или непринятая доза больше не сокращает курс — вместо неё автоматически создаётся новая доза дальше по графику, пока курс не отменят явно; «завершённость» курса в статистике теперь определяется отсутствием ожидающих доз, а не датой окончания
- Восстановление пароля по email («Забыли пароль?» на экране входа) — одноразовая ссылка со сроком действия, письмо логируется вместо отправки, если SMTP не настроен
- Мягкое удаление курса лечения (`Medication.is_deleted`, миграция `005`) — курс пропадает из вкладки «Препараты», но уже отмеченные дозы остаются видны в календаре; раньше `DELETE` каскадно стирал курс и все его дозы без возможности восстановить историю
- Реализована отмена курса из карточки дозы («🛑 Отменить курс» в модалке рядом с «Принято» / «Пропустить» / «Не принято»): дозы после выбранного дня стираются из календаря, дозы до и в этот день помечаются статусом `cancelled` и остаются в истории
- Новая вкладка «Статистика приёма» и эндпоинт `GET /medications/pet/{pet_id}/stats` — сводка (принято/пропущено/не принято) по каждому завершённому курсу
- Настраиваемое время напоминаний (`reminder_times`) — раньше время доз генерировалось всегда с 8:00 с равным интервалом, теперь пользователь задаёт время каждой дозы сам
- Понятное сообщение об ошибке при вводе имени пользователя вместо email на экране входа (раньше форма молча ничего не показывала), а также при других ошибках формы входа/регистрации
- Исправлен сдвиг даты на ±1 день в календаре (метка «Сегодня», выбор дня, дата отмены курса) — даты строились через UTC-конвертацию `toISOString()`, теперь берутся из локальных полей `Date`
